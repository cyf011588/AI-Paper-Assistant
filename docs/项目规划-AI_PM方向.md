## 二、竞品分析（核心：找差异化定位）

### 2.1 竞品全景

| 产品 | 核心能力 | 目标用户 | 优势 | 局限/空位 |
|---|---|---|---|---|
| **ChatPDF** | 单/多 PDF 上传后问答，带页码引用 | 学生、职场人、研究者 | 上手极快、免费额度够用、多文件文件夹 | 不理解论文结构（章节、双栏），只当通用文档处理；无知识库管理；无跨论文汇总 |
| **NotebookLM（现 Gemini Notebook）** | 多源上传 + 深度研究 + 思维导图 + 音频概览 | 学生、研究者、创作者 | Google 生态、1M 上下文、Deep Research、多格式支持 | 通用型工具，不针对学术论文优化；不保留章节层级元数据；无中文科研场景深度优化 |
| **Zotero + AI 插件** | 文献管理 + 第三方 AI 插件问答/摘要 | 重度科研用户 | 文献管理生态成熟、插件丰富（Lattice/PaperZorro/AI Butler） | AI 能力碎片化在第三方插件中，体验不统一；配置门槛高；无统一评估体系 |
| **智谱清言（ZScience）** | 通用 AI + 论文搜索/阅读/综述 | 中文科研用户 | 中文能力强、ZScience 找论文+读文献+写综述、国产大模型合规 | 通用助手定位，不是个人知识库；无论文结构感知；无长期知识沉淀 |
| **Scite.ai** | Smart Citations（引用支持/反对/提及分类）+ AI 助手 | 高校研究人员、图书情报 | 引用语义分析独一份、12 亿条引用语句索引、机构级数据 | 聚焦引用分析，不是个人论文知识库；不解决"我自己的论文怎么管、怎么问"的问题 |

### 2.2 差异化定位（你的项目立住脚的关键）

现有产品的共同空位：**没有一款产品真正解决"论文结构感知 + 个人知识沉淀 + 跨论文证据汇总"这三件事的结合。**

你的差异化定位可以是：

> **面向科研人员的「结构感知」个人论文知识库——不只是"跟 PDF 聊天"，而是理解论文的章节层级、保留来源上下文、支持跨论文的证据对比与汇总。**

三个差异化卖点：
1. **结构感知解析**：识别双栏排版、章节层级、图表标题，切分时不破坏论文语义（ChatPDF/NotebookLM 都做不到这一点）
2. **证据可追溯**：每个回答都能溯源到「哪篇论文 → 哪个章节 → 第几页」，而不是模糊的"第 N 页"
3. **跨论文对比**：支持在多篇论文之间做方法对比、结论汇总（而不只是单篇问答）

## 三、整体路线图（8 周计划）

### Phase 1：产品定义（第 1-2 周）—— PM 文档产出

| 产出物 | 内容 | 简历怎么用 |
|---|---|---|
| 竞品分析报告 | 上面这张表 + 差异化定位 | 面试时讲"我怎么看这个赛道的" |
| 用户画像与痛点 | 定义 2-3 个典型用户（如：研一新生读文献、研三写综述、青椒写基金） | 证明你懂用户，不是自嗨 |
| PRD 文档 | MVP 功能范围、优先级（P0/P1/P2）、验收标准 | 这是 PM 简历的核心弹药 |
| 指标体系 | 定义：检索命中率、问答准确率、引用正确率、用户满意度 | 证明你知道怎么衡量"产品好不好" |

### Phase 2：核心 Pipeline 搭建（第 3-5 周）—— 技术实现

**目标：跑通最小闭环**

```
PDF 上传 → 结构感知解析 → 结构感知 Chunking → Embedding → 向量入库 → 语义检索 → LLM 生成 → 带引用的回答
```

具体步骤：
1. **结构感知 PDF 解析**（在你现有代码基础上完善）
   - 你已经做了 block 分类（HEADING/BODY/FIGURE_CAPTION 等），继续完善
   - 输出结构化 JSON：每段文字带上 `section_hierarchy`（如 "3.2 Experimental Setup"）+ `page` + `paper_id`
2. **Chunking 策略**
   - 基线方案：固定大小切分（如 500 token + 100 overlap）
   - 你的方案：按章节边界切分，保留章节标题作为 chunk 的 metadata
   - 两种方案都跑，后面做对比实验
3. **Embedding + 向量数据库**
   - 用开源 embedding 模型（如 bge-small-zh 或 m3e）
   - 用 ChromaDB（轻量、本地、零配置）
4. **问答链路**
   - 检索 top-K chunks → 拼入 Prompt → 调用 LLM API → 返回答案 + 引用
   - LLM 用国产模型 API（DeepSeek / 通义千问 / 智谱 GLM，便宜且中文好）
5. **简单前端**
   - 用 Gradio 或 Streamlit，半天就能搭出来
   - 功能：上传 PDF + 聊天问答 + 右侧显示来源

### Phase 3：评估与迭代（第 6-7 周）—— 最体现 PM 能力

**这是简历上最有分量的部分：你怎么用数据驱动产品迭代。**

1. **构建测试集**（20-30 条问答对）
   - 从你的论文里人工构造：问题 + 标准答案 + 应该命中的论文/章节
   - 题型覆盖：事实提取、方法对比、结论汇总、跨论文推理

2. **对照实验**（至少做 2 组对比）
   - 实验 1：固定大小切分 vs 结构感知切分 → 检索命中率对比
   - 实验 2：top-K=3 vs top-K=5 vs top-K=8 → 问答准确率 vs 延迟
   - 记录每组实验的结果数据

3. **错误分析**
   - 把答错的 case 分类：是解析错了？切分错了？检索没召回？还是 LLM 生成幻觉？
   - 针对最大的问题做一轮优化，记录提升了多少

4. **输出迭代日志**
   - 格式：`问题 → 假设 → 改动 → 结果 → 结论`
   - 这就是你简历上"迭代优化"那一条的素材

### Phase 4：打磨与简历（第 8 周）

- 录一个 2-3 分钟的演示视频（上传论文 → 提问 → 展示来源）
- 写好 README（架构图 + 功能截图 + 实验结果表格）
- 把 GitHub 仓库整理干净
- 改简历

## 五、我们怎么协作（AI 协助开发）

你不需要自己从零写代码。我们的工作方式：

1. **你负责**：产品决策（功能要不要做、优先级怎么排）、测试集构造（你是土木研究生，你知道怎么读论文）、结果判断（答案对不对你能看出来）
2. **我负责**：写代码、调 bug、搭 Pipeline、写文档、做数据统计
3. **工作流程**：你告诉我"我想要什么功能" → 我写代码给你 → 你跑一下看效果 → 不对的地方告诉我 → 我改

**你需要提前准备的**：
- 把你要测试的论文放到 `data/papers/` 目录下（至少 5-10 篇，越多测试越可信）
- 想好你要问什么类型的问题（测试集的种子）
- 准备一个大模型 API Key（DeepSeek 最便宜，1 块钱能用很久）
